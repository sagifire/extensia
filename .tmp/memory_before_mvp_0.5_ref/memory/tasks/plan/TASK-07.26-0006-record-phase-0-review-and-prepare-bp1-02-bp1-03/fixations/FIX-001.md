### Контракт canonical task `BP1-02`

- Мета: реалізувати чисте domain-contract ядро для прийнятих у FIX-003 Phase 1 scalar, JSON і detached readonly DTO boundaries без Core/storage/runtime behavior.
- Scope: branded `IDString`/`Timestamp`; UUID v4 generation/parsing/normalization; timestamp validation/conversions; recursive readonly JSON value/object types and validators; DTO types для Resource/Asset/Mark/KV та projections, перелічених target model; detached snapshot builders; pure validators лише для accepted invariants.
- Out of scope: Core, storage, facades, mutation pipeline, persistence/schema versioning, size limits, exact public facade inputs/results, а також будь-які відповіді на відкриті delete/order/update/normalization policies.
- Dependencies: green `BP1-01`; applied FIX-003 TASK-07.26-0003 як authority для прийнятих scalar/DTO boundaries; `domain/target/model.md`, `domain/rules.md` і `domain/open-questions.md` як target-draft constraints без стабілізації exact field/public signatures.
- Acceptance: canonical UUID/timestamp/JSON boundaries enforced; deep readonly types; no mutable aliases; accepted Resource/Asset/Mark/KV invariants мають pure validators/tests; open-question behavior не вигадано; package root не розширено speculative exports.
- Verification: unit boundary/property-style cases, compile-time type tests, JSON roundtrip, invalid UUID/date/number/Mark/Asset combinations, alias mutation test, full BP1-01 package gates.
- Memory sync: оновити factual domain current implementation state і task/run artifacts; target memory змінювати лише через окрему fixation при доведеному discrepancy.
- Architecture pressure: не переносити runtime orchestration або persistence semantics у domain kernel; виявлений тиск виносити у design/ADR/follow-up.

### Контракт canonical task `BP1-03`

- Мета: побудувати internal IoC composition skeleton на exact `@sagifire/ioc@0.0.2`, який доводить module/token/port boundaries і fail-fast diagnostics без public IoC leakage та без lifecycle controller Phase 1 WP4.
- Scope: namespaced internal tokens; consumer-owned narrow ports і adapters; single/multi cardinality; єдиний Composition Root; graph validation/normalized diagnostics; safe immutable inspection snapshot; fresh-composition conformance harness; точні package capability tests. Conformance використовує явно test-only probe modules. Набір production `extensia.*` subsystem modules не реалізується неявно: його вибір відкладається до BP1-04 або окремого design gate.
- Out of scope: public facades/plugin API, lifecycle startup/rollback controller, Core/write engine, storage/journal/recovery, dynamic extensions, public tokens/subpaths, domain contracts BP1-02.
- Dependencies: green `BP1-01`; accepted ADR-0003/ADR-0006; `technical/architecture.md`, `technical/rules.md` і `technical/open-questions.md` як target-draft constraints; може реалізовуватися паралельно з BP1-02 після tooling gate.
- Acceptance: missing port/cycle/duplicate/cardinality/private-provider cases fail до runtime startup; `compose()` повертає immutable capabilities; private providers inaccessible; package root не експортує raw runtime/tokens; synchronous contribution limitation encoded; diagnostics safe.
- Verification: graph/diagnostic contract suite, private-access and adapter-source assertions, single/multi cardinality cases, scope/disposal smoke, fresh-composition isolation, root export check, full BP1-01 package gates.
- Memory sync: оновити factual technical/current implementation state, task/run artifacts і точні divergence notes; accepted ADR decisions не змінювати без fixation, а target-draft architecture не видавати за стабілізований contract.
- Architecture pressure: заборонити service locator, другий composition root, mutable post-compose overrides або передчасне включення lifecycle/Core.
