## Exact invariants

- Active sibling group визначається exact `parent_id` і `is_deleted = false`; `order_index` утворює permutation `0..n-1`.
- `moveResource` використовує insertion index після removal, range `0..destinationCount`, без clamp; cycle/orphan/deleted-parent/no-change мають exact normalized outcomes.
- Root create append-иться з `order_index = activeRootCount`; move/delete stage-ять лише effective changed Resources з common operation timestamp.
- Delete є leaf-only soft delete, зберігає tombstone metadata/aggregates, reindex-ить active siblings, default reads ховають tombstone; restore/include-deleted/cascade/purge deferred.
- `setMarks` є full replacement до 256 exact unique sorted Marks; `setKV` replace-ить один namespace, empty mapping deletes namespace, із exact count/string/total limits і deterministic key order.
- Pre-session `resource_hints` не є authority. Immutable `PreparedResourceWriteSet` після coherent load є єдиним джерелом exact sorted staging, fingerprint, journal IDs і changes.
- Рівно один semantic commit і one committed journal entry охоплюють весь prepared write-set; batch prepared index publication є atomic visibility boundary після commit.
- Typed durable/index integrity defect до commit дає `STORAGE_INTEGRITY_FAILED`, safe `operation` diagnostic і synchronous no-await engine close/facade unpublication/Module failed до cleanup; ordinary I/O/lock failures не перекласифіковуються, post-commit faults лишаються committed warnings.
- Public methods/types/error unions мають exact compile-oriented snapshot; public transaction/Core/IoC/driver internals не експортуються.
