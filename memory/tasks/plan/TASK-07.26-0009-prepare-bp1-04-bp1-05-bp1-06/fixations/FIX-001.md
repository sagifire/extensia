- Мета: реалізувати lifecycle-only architecture-enabling slice `construction -> compose -> start -> ready/failed -> stop/dispose` поверх завершених domain та IoC foundations.
- Scope: side-effect-free Extensia Module construction boundary; internal Runtime Controller; мінімальний набір production lifecycle modules/capabilities, потрібний лише цьому slice; readonly deterministic fake Storage Driver contract/binding; explicit module/controller state machines; ordered startup stages; reverse rollback; guaranteed runtime disposal; safe lifecycle diagnostics/inspection; fresh-composition harness; packed application-boundary smoke.
- Public/API boundary: до activation implementation обов'язковий окремий owner-approved design/fixation gate, який фіксує exact мінімальний root lifecycle contract: exported symbol/factory/class, construction/config input, lifecycle result/state shape, inspection exposure і compatibility status. `storage`, `query`, facades, plugins/extensions і final config shape поза цим мінімумом не реалізуються. Conceptual signatures source specifications не є authority цього gate.
- Out of scope: Resource queries, facade registry, public facades/plugin API, Core operation behavior, full Storage Driver, journal/index/recovery/write/sync, production subsystem map beyond lifecycle slice, dynamic extensions.
- Dependencies: accepted `BP1-01`, `BP1-02`, `BP1-03`; окремий applied owner-approved design/fixation gate exact minimal root lifecycle contract; ADR-0003/ADR-0006; technical architecture/rules/open questions як constraints, не authority для exact draft signatures. Без applied public-contract gate BP1-04 лишається `backlog` і `RUN-001` не створюється.
- Acceptance: construction без active side effects; ready публікується лише після всіх required stages; failure injection на кожному stage виконує deterministic reverse cleanup і runtime disposal; partially initialized capabilities не стають ready/public; stop має explicit bounded/idempotency-aware policy, агрегує cleanup failures без втрати решти cleanup; diagnostics/inspection detached, immutable й safe; fresh instances не ділять mutable lifecycle state; package smoke доводить start/stop через дозволену application boundary без raw IoC leak.
- Verification: lifecycle transition matrix; injected failure/cleanup-order matrix; double/concurrent start/stop policy tests; resource leak/disposal assertions; fake driver lifecycle contract; safe diagnostics sentinel tests; fresh composition isolation; root export and packed Node 24 smoke; full package gates.
- Memory sync: factual technical/current implementation state, task/run artifacts, state після accepted result; target architecture/ADR змінювати лише при confirmed discrepancy через окрему fixation.
