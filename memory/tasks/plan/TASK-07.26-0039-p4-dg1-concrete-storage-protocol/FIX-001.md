## Target files і exact proposed changes

### 1. `memory/technical/decisions/ADR-0010-local-sqlite-storage-protocol.md` — create

Створити ADR зі статусом `accepted`, який дослівно фіксує:

- перший concrete driver — internal `local-sqlite-v1`: Node.js 24 `node:sqlite`, одна SQLite durability domain для metadata, journal і майбутніх opaque payload chunks; external blob publication у baseline заборонена;
- support boundary: proposed Windows 11 local NTFS, one host, one full writer; certification лише після P4-WP1 crash/lock proof; Linux ext4/XFS candidate до окремої certification; network/removable/sync/FUSE/direct mutation unsupported;
- rollback journal, `synchronous=EXTRA`, dedicated `locking_mode=EXCLUSIVE` connection як lease від session acquire до release, no PID/stale lock file;
- SQLite transaction одночасно записує logical metadata, operation fingerprint і рівно один committed journal row; `journal` є єдиним committed journal;
- arbitrary-length canonical decimal sequence зберігається як TEXT/length+lexical; write-set fingerprint не unique між різними operations;
- COMMIT error обов'язково класифікується через connection `isTransaction`, rollback/retry та exact query by `operation_id`; settled resolve = proven committed, settled reject = proven absent. Persistent unclassifiable storage failure закриває intake й може лишити commit promise pending до відновлення доступу або external process termination: safety гарантується, liveness ні;
- full recovery-before-ready та readonly no-write/fail-if-recovery-required;
- exact physical root містить лише driver-owned `extensia.sqlite3` і SQLite-private rollback journal; logical IDs не стають paths; symlink/reparse/non-regular DB target відхиляється; `application_id`, `user_version=1`, singleton format marker, schema/quick-check, canonical JSON/fingerprint/sequence/payload integrity fail-close до ready; device power-loss, network filesystem, dishonest cache і uncertified filesystem guarantees unsupported;
- implementation gate: child-process cut-point, fault injection, dual-platform local-FS CI, exclusive-lock-through-COMMIT, readonly/corruption/payload-size proof.

ADR має послатися на P4-DG1 report і зафіксувати alternatives: pure fs, all-in-SQLite BLOB, native adapter.

### 3. `memory/technical/architecture.md`

### 4. `memory/technical/rules.md`

Додати invariants:

- concrete commit exception не може стати reject до durable reconciliation;
- outcome-definite означає definite settled value; persistent unavailable durability domain може призупинити settlement/runtime і не перетворюється на ambiguous rejection;
- external filesystem blob publication заборонена у baseline; payload і journal commit належать одній SQLite transaction;
- SQLite `journal` є єдиним journal authority; independent append заборонений;
- PID/stale lock files, network filesystem claims і layout leakage заборонені для baseline profile;
- readonly path не виконує recovery/cleanup writes.

## Rationale

Proposal усуває physical durability ambiguity без layout leakage й без паралельного journal path. SQLite є єдиною transaction/recovery/locking/payload durability domain; cross-store atomicity не заявляється.

## Impact

- Product: відкриває preparation P4-WP1 лише після application/publication/post-audit.
- Domain: не змінює Resource або Asset semantics.
- Technical: додає bounded physical profile й ADR; P3 semantic invariants збережені.
- Runtime/API: public surface не змінюється.
- Dependencies/code: цим FIX не змінюються.

## Risks

- `node:sqlite` RC і synchronous API потребують isolation/CI/performance proof.
- Physical guarantees залежать від tested local filesystem/device.
- Commit reconciliation, exclusive lease та large-payload performance складніші за happy-path transaction.
