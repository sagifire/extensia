## Точний manifest

- Створити `memory/technical/public-read-contract.md` з literal root/type snapshot, side-effect-free factory і повною config-envelope semantics: own data-property extraction не викликає getters/accessors; malformed/accessor envelope стає internal sentinel і `start()` повертає `CONFIG_INVALID` до відкриття resources; driver identity capture-иться в новий frozen normalized envelope; зовнішній envelope після construction не reread; driver object не clone/freeze. Також зафіксувати lifecycle/publication, два reads, experimental readonly boundary, Registry/provenance, failure matrices, diagnostics і compatibility labels.
- Створити `memory/technical/decisions/ADR-0007-minimal-public-read-contract.md` як accepted decision для factory/module/result/facade publication/shared seam разом із explicit rejected alternatives; синхронізувати direct technical та ADR indexes.
- Оновити лише approved portions у `technical/architecture.md`, `technical/rules.md`, `technical/open-questions.md`, `domain/target/model.md`, `product/roadmap.md`, `state.md`, plan indexes/progress і canonical BP2-02/BP2-03 task contracts.
- Створити backlog-only `BP2-01A / TASK-07.26-0022` з `Type: chore` і `Execution Mode: autonomous-implementation`, що materialize-ить exact source-only internal read-port/token artifact у `src/system-extensions/default-api/resource-read-port.ts` без runtime implementation. До окремої activation не створювати `RUN-*` або інші execution artifacts.

## Мапа canonical застосування

- `technical/architecture.md`: додати bounded Phase 2 read boundary — root factory/config capture із internal sentinel/`CONFIG_INVALID` before resources і no reread caller envelope, exact two reads, frozen publication, dedicated accessors, experimental readonly proof і один shared seam; не заявляти реалізацію або готовність production module map.
- `technical/rules.md`: додати canonical facade naming і reserved provenance, заборону silent normalization та parallel test-only read contract, а для Phase 2 readonly proof — capability failure до input validation/mutation.
- `technical/open-questions.md`: закрити тільки P2-DG1 portions: exact Phase 2 methods/result shape, Phase 2 naming/freeze/Registry ownership. Залишити відкритими final write inputs, final driver protocol, повний error catalog, plugins/custom facades і release compatibility policy.
- `domain/target/model.md`: замінити deferred exact P2 facade gate direct reference на public read contract; scalar, JSON-safe DTO та snapshot fields не змінювати.
- `product/roadmap.md`: factual `P2-DG1` позначається applied лише після canonical application; послідовність waves, dependencies та наступних tasks не змінюється.
- `state.md`, `tasks/plan/index.md`, `tasks/plan/progress.md`: відобразити factual application status/artifact, prepared BP2-01A і conjunction gate без activation наступних задач.
- BP2-02/BP2-03 `task.md`: обидва посилаються на `APP-07.26-0021-001`, `done` BP2-01A та власне окреме activation decision; дозволена паралельність існує тільки після цих трьох умов.
