## Призначення

Зафіксувати Phase 1 baseline для `IDString`, numeric `Timestamp` і readonly JSON-safe detached DTO snapshots.

## Підсумок джерела

Research порівняв draft 64-bit ID із standard UUID, numeric time units і runtime/type-level snapshot guarantees. Recommendation: canonical lowercase UUID v4, integer Unix epoch milliseconds, deeply readonly JSON-only DTOs без shared mutable references.

## Запропоновані зміни

- `IDString`: branded string із canonical lowercase RFC 9562 UUID v4; generation через `crypto.randomUUID()`; raw parser приймає тільки hyphenated UUID v4, нормалізує hex case до lowercase й відхиляє інші versions/forms; JSON string.
- Відхилити draft custom 64-bit timestamp+32-bit-random algorithm як insufficient collision baseline.
- `Timestamp`: branded number, safe integer milliseconds від Unix epoch UTC, ECMAScript Date range, JSON number, explicit Date conversion; string/Date union прибрати з canonical contract.
- Зафіксувати, що Timestamp не задає total ordering; journal sequence окремий.
- DTO properties/arrays/maps зробити deeply readonly; `Asset.data` обмежити readonly JSON object або `null`; заборонити undefined/Date/bigint/functions/symbols/NaN/infinity.
- Snapshot має бути detached від internal mutable state; runtime freeze не є compatibility guarantee.
- У open questions закрити три base-type questions; size limits, schema evolution і exact facade inputs лишити owner gates.

## Обґрунтування

Рішення використовують standard runtime primitives, дають стабільну JSON representation і не змішують identity/time із journal ordering. Detached readonly contract безпечний для facade DTO й driver serialization.
