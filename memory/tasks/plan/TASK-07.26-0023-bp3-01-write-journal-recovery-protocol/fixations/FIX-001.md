## Підсумок джерела

RSCH-001 рекомендує driver-owned layout-neutral write session і transaction, де `commit(entryDraft)` є outcome-definite semantic linearization point для Resource metadata та рівно одного committed journal entry. Core лишається policy owner, готує validated next snapshot/index delta до commit і публікує index після commit. Journal baseline committed-only; recovery використовує driver-private staging і завершується до ready. Перші public writes обмежені root create та update `title`/`description`.

### Exact decisions proposed

- `ResourceWriteTransaction.commit()` одночасно фіксує staged Resource metadata й committed entry; resolve = committed, reject = not committed. Idempotency порівнює canonical SHA-256 fingerprint повного ordered staged write-set, не лише journal hints.
- Sequence є canonical positive decimal string, починається з `1`, contiguous/gap-free і призначається driver під exclusive storage session; unknown/ahead/missing cursor є integrity failure, Timestamp не задає order.
- Persistent baseline journal містить тільки committed entries; started/failed/rolled-back є runtime diagnostics або driver-private staging.
- Operation ID/actor ID є internal UUID v4; commit idempotent для identical operation ID/draft, mismatch є integrity failure; public idempotency deferred.
- Core reload-ить current state під storage session, готує validated immutable index delta до transaction і publish-ить no-fail swap після commit.
- Full startup: open -> acquire recovery-clean exclusive storage session -> committed scan/index/journal-head capture під тією самою session -> release -> ready. Session acquisition після crash іншого writer також відновлює або відхиляє ambiguous state.
- Create input: exact own `title`, optional `description`; generated root defaults. Update: exact own optional `title`/`description`, at least one effective change. Root type snapshot містить exact result/error/warning union і readonly/full driver config union.
- Після committed resolve current command завжди повертає committed `ResourceWriteSuccess`; post-commit index/cleanup fault додає bounded warning, fail-close/unpublish-ить module і не стає failure/throw. `stop()` із failed виконує cleanup і переходить у stopped.
- Generated ID collision має at most three candidates/attempts total; кожний collision виконує release storage session -> release old local lock -> regenerate/replan, а collision третього candidate повертає `RESOURCE_ID_GENERATION_FAILED` без lock inversion.
- Public full driver є frozen opaque handle, створений `defineFullResourceDriver(definition)` через private WeakMap capture. Config/facades/Module не розкривають callable session/transaction; raw callbacks існують лише в окремій experimental driver-author definition boundary.
- Root runtime value `defineFullResourceDriver` має explicit `experimental-driver-author` label; existing `createExtensia` compatibility не змінюється цим label.
- Readonly failure перед input inspection зберігається. Parent/order/flags/Mark/KV/delete/Assets/hooks/sync/concrete layout не входять у contract.
- Full driver і create/update compatibility мають label `experimental-phase-3` до P4/P7 gates.
