## Мета run

Виконати свіжу стабілізацію чистого стану, пакета, API й архітектури всієї фази 3 для create/update/order/move/delete/Marks/KV, побудувати простежуваність і матриці доказів, обмежено виправити доведені дефекти фази 3, пройти незалежний аудит і підготувати докази фази 3 до human review без зміни design або розширення можливостей.

## Ефективні вимоги

- Чисте встановлення, збірка, типи, тести, lint, форматування, пакет, tarball, packed consumer і відтворюваність.
- Точність публічних API, помилок, діагностик та експортів для create/update/move/delete/Marks/KV.
- Щільний order, active-parent, видимість tombstone, канонічність aggregate і незмінні властивості відокремленого DTO.
- Точки відмов, фіксації з одним записом, попередження, відновлення, типізована integrity, відкладений cleanup і розклади конкурентності.
- Сканування джерел на дублікати шляхів і повноважень та витік відкладеної поведінки.
- Редагування production-коду дозволені лише для виправлення доведених дефектів фази 3 в наявних стиках facade/Core/domain/operation/driver/index/lifecycle і тестах; нові можливості заборонені.
- Зміни package/config/exports дозволені лише коли їх вимагає точна знахідка щодо кореня, packed output або відтворюваності; зміни залежностей чи версій потребують окремих повноважень.
- Оновлення пам'яті охоплюють фактичний поточний стан домену, технічну архітектуру або стек, task result/progress/state/indexes і явний статус gate фази 3; зміни канонічного design потребують ізольованого виправлення й рішення людини.
- Спочатку виявити скрипти репозиторію; виконати цільові матриці, потім `npm run check`, точні скрипти пакета, tarball і packed output, `git diff --check` та сканування джерел і експортів.
- Зафіксувати версії Node/npm, точні команди, кількості тестів, переліки артефактів і hashes, де застосовно, та стани знахідок до й після виправлення; не успадковувати твердження про зелений стан із попередніх задач.
- Після виправлень обов'язковий незалежний аудит; відкритих P0-P3 не має бути.
- `result.md` має розрізняти нові докази й успадковані результати, містити різницю scope/no-scope, усі стани пам'яті загального рівня, мовний контроль, архітектурний тиск, залишкові ризики й подальші дії та запит на human review фази 3.

- Матриці API, семантики, протоколу, відмов і відновлення, integrity, конкурентності, пакета й відтворюваності.

- Точні кореневі експорти, packed consumer, чистота згенерованих артефактів, перелік tarball і порівняння байтів та вмісту для відтворюваності.
- Фактична синхронізація пам'яті та явний статус gate фази 3.
