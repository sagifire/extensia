## Поточні гарантії

На current implementation boundary фактично гарантуються canonical UUID v4 normalization/validation, safe-integer Timestamp у ECMAScript Date range, finite JSON-safe recursive values, deeply readonly type contracts, detached snapshot ownership, executable IoC composition conformance, lifecycle `compose -> start -> ready/failed -> stop/dispose`, bounded greedy Resource read model і frozen Facade Registry з atomic ready publication. Public Extensia Module мапить ці guarantees у normalized application results та safe inspection; lifecycle/facade failures містять тільки Extensia-owned codes, stages і validated safe subjects, без raw error details, provider values, config або runtime instances. Resource та Asset writes використовують один consumer-owned Core/Operation Engine і driver-owned semantic commit/journal/index path; readonly storage adapter не читає command input. Root namespace містить лише runtime values `createExtensia`/`defineFullResourceDriver` та exact public type exports, package не відкриває internal subpaths. Internal concrete `local-sqlite-v1` physical durability, повна Phase 3 Resource parity, P4-VS2 Asset metadata/staged-generation persistence та P4-VS3 opaque upload capability/lifecycle реалізовані й перевірені bounded Windows local NTFS process-crash, fake-vs-SQLite, packed, restart, integrity і pressure evidence. Internal stage/read, begin/finish/abort та atomic publish/discard є current, а P4-STAB cross-phase stabilization і explicit Phase 4 human gate прийняті; ordinary public bytes/file API, P7 compatibility freeze, final/public Storage Driver surface і power-loss certificate відсутні; P5 coherent generation, lazy complete-only Resource reads, semantic explicit refresh/config/inspection і concrete SQLite multi-instance sync/polling є current experimental implementation без topology support claim до P5-STAB/P5-AUD1/human gate. Цільові інваріанти ширших slices описані окремо в `memory/domain/target/model.md` і `memory/domain/rules.md`.

## Межа current/target

Resource/Asset/Mark/KV data-contract kernel, IoC composition/conformance skeleton, generic internal lifecycle host, bounded Core Resource index, shared internal Facade Registry, default system facade adapters, public Extensia Module reads та experimental Resource create/own-metadata update/move/leaf-soft-delete, full-replace Mark writes, namespace-replace/delete KV writes і Asset metadata create/update/set-primary/reassign/delete є current implementation. Asset command boundary має descriptor-safe exact parsing, shared storage-wide invariants, common Resource/Asset timestamp, exact logical payload action/`asset_changes` journal seam, concrete staged-generation persistence та internal opaque upload capability. Internal `local-sqlite-v1` adapter, exact schema/format gate, one-transaction Resource/Asset/journal commit, exclusive lease, COMMIT reconciliation, versioned `1 → 2` migration, bounded stage/read, begin/finish/abort, atomic payload publication/discard, startup payload integrity і process-crash proof також є current implementation. Internal `createLocalSqliteExtensia` є production composition owner для full/readonly concrete runtime, але не package API; через нього accepted Resource, Asset metadata й internal bytes semantics доведені на реальному SQLite без другого Core, operation contract, index або journal path. Accepted P4-STAB підтверджує current bounded Phase 4 durability path, але не означає наявність application-facing bytes transport/file read facade, streaming, external blobs, P7 compatibility freeze, restore/include-deleted/cascade/purge/retention, final/public Storage Driver surface, broader physical certification, plugin/custom facade API або public concurrency/retry policy.
