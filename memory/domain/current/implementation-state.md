## Поточні гарантії

На current implementation boundary фактично гарантуються canonical UUID v4 normalization/validation, safe-integer Timestamp у ECMAScript Date range, finite JSON-safe recursive values, deeply readonly type contracts, detached snapshot ownership, executable IoC composition conformance, lifecycle `compose -> start -> ready/failed -> stop/dispose`, bounded greedy Resource read model і frozen Facade Registry з atomic ready publication. Public Extensia Module мапить ці guarantees у normalized application results та safe inspection; lifecycle/facade failures містять тільки Extensia-owned codes, stages і validated safe subjects, без raw error details, provider values, config або runtime instances. Resource та Asset metadata writes використовують один consumer-owned Core/Operation Engine і driver-owned semantic commit/journal/index path; readonly storage adapter не читає command input. Root namespace містить лише runtime values `createExtensia`/`defineFullResourceDriver` та exact public type exports, package не відкриває internal subpaths. Internal concrete `local-sqlite-v1` physical durability, повна Phase 3 Resource parity й P4-VS2 Asset metadata/staged-generation persistence реалізовані та перевірені bounded Windows local NTFS process-crash, fake-vs-SQLite, packed, restart і pressure evidence. Bytes transport/finalization, P5 indexes/sync, P7 compatibility freeze, final/public Storage Driver surface і power-loss certificate відсутні. Цільові інваріанти ширших slices описані окремо в `memory/domain/target/model.md` і `memory/domain/rules.md`.

## Межа current/target

Resource/Asset/Mark/KV data-contract kernel, IoC composition/conformance skeleton, generic internal lifecycle host, bounded Core Resource index, shared internal Facade Registry, default system facade adapters, public Extensia Module reads та experimental Resource create/own-metadata update/move/leaf-soft-delete, full-replace Mark writes, namespace-replace/delete KV writes і Asset metadata create/update/set-primary/reassign/delete є current implementation. Asset command boundary має descriptor-safe exact parsing, shared storage-wide invariants, common Resource/Asset timestamp, exact logical payload action/`asset_changes` journal seam і concrete staged-generation persistence. Internal `local-sqlite-v1` adapter, exact schema/format gate, one-transaction Resource/Asset/journal commit, exclusive lease, COMMIT reconciliation, versioned `1 → 2` migration, readonly/recovery/integrity behavior і bounded process-crash proof також є current implementation. Internal `createLocalSqliteExtensia` є production composition owner для full/readonly concrete runtime, але не package API; через нього accepted Resource й Asset metadata semantics доведені на реальному SQLite без другого Core, operation contract, index або journal path. Це не означає наявність Asset bytes transport, begin/finish/abort, payload publication/read, P5 global indexes/sync, P7 compatibility freeze, restore/include-deleted/cascade/purge/retention, final/public Storage Driver surface, broader physical certification, plugin/custom facade API або public concurrency/retry policy. Після кожного implementation run цей документ треба синхронізувати з фактичним кодом і tests.
